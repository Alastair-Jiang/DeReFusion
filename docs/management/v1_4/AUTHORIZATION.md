# 授权边界 v1.1

本规则依据用户在当前会话给出的项目代理负责人授权制定。它是项目内部行政决定，不是数据商、机构、账户所有者的批准，不是导师签名。Codex 可修订本规则，但须形成新版本、说明理由和受影响范围。

## 决策权与责任

| 主体 | 责任与权限 |
|---|---|
| 用户 | 保留重大费用、难以恢复的数据丢失、超出项目范围以及未单独授权的对外沟通等决定 |
| Codex 代理负责人 | 研究问题、工程方案、优先级、工作分配、协议修订、证据验收和分阶段执行放行；对结论负责 |
| DSH | 接到具体任务后独立复核指定版本；指出问题并给证据；复核意见不自动成为执行许可 |
| OpenClaw / 其他执行 agent | 按具名任务、输入 pin、输出目录和预算执行；不能凭接管口号扩大数据或发布权限 |

一个任务只有一个最终负责人与一个写入所有者。DSH 当前未被本包冒名记录为已审通过；也未创建任何 OpenClaw 后台任务。

## 动作分层

| 层级 | 动作 | 当前规则 |
|---|---|---|
| A：自主 | 项目文件盘点、来源追溯、方案和代码修改、合成测试、常规验证、文档整理 | 可以直接做；保留历史与已有改动；不得借元数据任务读取秘密 |
| B：条件自主 | 真实数据 QA、预处理、拟合、评分、分析 | 用户已委托决策；由 Codex 检查具体数据使用依据、协议与技术准备，签发有输入哈希、范围、预算和终止条件的 release 后做 |
| C：审核后发布 | 已授权远程上的普通文档/代码提交和普通推送 | 范围审核、独立复核、秘密和许可检查、差异检查后执行；不批量加入数据、权重、预测数组或日志 |
| D：用户保留 | 历史重写/强推、删除不可恢复材料、重大费用、仓库可见性变更、未授权外部消息或上传目的地 | 完成可逆准备，提交具体影响及恢复方案，再请求对应决定 |

数据内部研究使用、公开原始数据、公开权重/预测/衍生结果分别判定。没有公开再分发许可不自动证明内部研究不可行；未知使用依据也不能被代理授权替代。可以依据适用条款、已有许可或其他可核验依据，不一律要求供应商签字。无法核实则阻断相关数据的相关动作，不能阻断无关文档和合成验证。

## 执行放行与停止

Release 必须写明：决策人、时间、仓库/分支/HEAD/dirty diff 身份、协议与源码哈希、数据合同、准许的阶段与输入根目录、产物目录、设备和预算、失败处理、撤销条件。每阶段完成后检查产物身份才能进入下一阶段。

数据资格检查 release 可以先于完整训练 release：可信保管人仅做来源/字节/日期/单位/质量检查，记录已接触测试数据，不向拟合 worker 传递测试值。预处理 release 再生成角色化数据包；拟合 release 不含测试包；冻结后才给 evaluator 测试访问。这样避免“必须先运行才能补齐放行字段”的循环。

遇到 pin 漂移、越界读写、标签/键不齐、非有限数值、预算越界、来源依据失效时立即停止受影响阶段，写事件。不可自动改资产、删失败 seed、降精度或重跑到好结果。修复后新 attempt，新 release；保持旧记录。

未另行指定的合成/工程验证行政预算：单进程、最多 2 CPU 线程、单命令 30 分钟、单批累计 2 小时、新增输出 2 GiB、付费 0。达到上限停止并由负责人重新评估。R1 已批准的专属预算只在其具体 release 签发后使用，不由通用预算扩大。

## 旧控制记录如何处理

| 旧记录 | v1 的处理 |
|---|---|
| 会话早期“本轮仅文档、无训练/提交权限” | 用户后续广泛委托已扩展行政权限；不再当作永久禁令 |
| R1_APPROVED_DESIGN_V1.json | 原文件不改；设计身份保留，后续 release 是追加记录 |
| R1_EXECUTION_GATE_DECISION_V1.md 的 NOT_AUTHORIZED | 保留为当时执行事实；本包未补齐其技术条件，也未将其改成已放行 |
| Phase 1 预注册、Stage C/D 决策 | 保留科学约束和历史身份；新方案新版本，不能追溯修改统计设定 |
| 数据条款、机构要求、账户/费用权限 | 不能被内部规则覆盖，按具体适用范围核验 |

旧文件中重复要求人类逐项批准的项目内部程序，可由有证据的代理负责人决定替代；技术缺口和外部边界不因行政委托而消失。本包是管理规则与记录格式，尚未接入运行器成为自动强制检查。
