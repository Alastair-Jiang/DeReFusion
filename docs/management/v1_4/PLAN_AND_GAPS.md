# 执行计划与缺失信息

本清单区分管理制度、可定位的历史记录和仍未核实的事实。所有缺口由 Codex 负责推进；DSH 独立检查指定哈希。无法找回的历史信息不补造。

## 执行次序

1. **M0 管理基线**：v1 已由 DSH 审查并要求修订；v1.1 已按问题更新，等待对新 manifest 的复核。意见闭环后再评估范围受控的普通提交。
2. **M1 数据与运行证据**：追查逐文件来源/使用依据（G01–G03），补 receipt、环境和产物身份链（G10–G11），厘清 freeze-summary 来源（G04）。只处理适用范围，不把缺失权利误作全项目封锁。
3. **M2 R1 准备**：补全数据 QA 合同、共同键和角色包（G05–G06）；独立复核 F/B 合成生命周期和 T0 负例（G07–G08）；给 12 小时硬预算提供含 overhead 的合成计时方案。
4. **M3 分阶段执行**：资格检查、预处理、拟合、冻结、评分分别记录阶段 release。数据使用依据、技术证据和每阶段预算满足前置条件后，代理负责人签发限定范围的 release。当前没有真实执行 release。
5. **M4 研究判断**：R1 保持探索性；依据完整分层结果再决定独立确认。Stage D、跨硬件统一排名和新确认方案各有独立条件，不因本管理包而启动。
